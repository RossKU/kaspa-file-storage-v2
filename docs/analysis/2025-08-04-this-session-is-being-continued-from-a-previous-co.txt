  1. 共通の追加関数を作成
  // ダウンロード成功時のKENV自動登録
  async function addDownloadedFileToKENV(metadata, metaTxId, blockId, password) {
      // 重複チェック
      const existing = FileState.kenvManager.entries.find(e =>
          e.metaTxId === metaTxId
      );

      if (!existing) {
          const fileName = metadata.file?.name || metadata.directory?.name || 'unknown';
          const fileType = metadata.type || 'kaspa-file';

          // 新規エントリ追加
          const entry = FileState.kenvManager.addMinimalEntry(
              fileName,
              fileType,
              'download'  // sourceを'download'に
          );

          // メタデータ設定
          entry.metaTxId = metaTxId;
          entry.metaTxBlockId = blockId;
          entry.fileSize = metadata.file?.size || 0;
          entry.mimeType = metadata.file?.mimeType || '';
          entry.password = password;
          entry.status = 'verified';

          // インデックス更新
          const lineNumber = FileState.kenvManager.entries.indexOf(entry);
          FileState.kenvManager.updateIndex(entry, lineNumber);

          // 保存
          await FileState.kenvManager.saveAll();

          // UIを更新（ファイルタブがアクティブな場合）
          if (document.querySelector('.tab-content.active')?.id === 'file-tab') {
              window.updateFileListFromKENV();
          }

          log(`[KENV] ダウンロードしたファイルを自動登録: ${fileName}`, 'info');
      } else {
          log(`[KENV] 既に登録済み: ${existing.name}`, 'info');
      }
  }

  2. downloadFileFromDirectoryの修正（14186行付近）

  },

  ログ分析結果

  主な問題：

  [ERROR] writable作成エラー: An operation that depends on state cached in an interface object was made but the state had

    - Android/Termux環境でのFile System API使用時の問題
    - 作業フォルダ設定直後にKENVを初期化している（89-96行目）
  2. WebSocket頻繁な切断
    - 1分ごとに切断・再接続を繰り返している
    - ネットワークの不安定性が原因
  3. メタトランザクション作成失敗（280行目）
  [ERROR] メタトランザクション作成エラー: RPC Server (remote error) -> WebSocket -> WebSocket is not connected
    - WebSocket切断中にメタトランザクションを作成しようとした

  v5.11.115の問題点

  実装自体に致命的な問題はないが、以下の改善点がある：

  1. KENVマネージャー未初期化時の処理
    - FileState.kenvManager.entriesが存在しない場合のエラーハンドリング不足
  2. ワークスペース未設定時の動作
    - LocalStorageモードとワークスペースモードの混在時の処理

  結論

  - v5.11.115の変更が直接的な原因ではない
  - File System APIとWebSocketの問題が主な原因

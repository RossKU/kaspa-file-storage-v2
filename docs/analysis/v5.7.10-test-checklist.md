# v5.7.10 テストチェックリスト

## 概要
v5.7.10では、processAndUploadの2重実行を防止し、トランザクション重複送信を解決しました。

## 重要な確認ポイント

### 1. 正常なアップロード処理
- [ ] ファイルアップロードが通常通り動作すること
- [ ] 進捗表示が正しく更新されること
- [ ] 完了まで問題なく処理されること

### 2. ネットワーク切断時の動作

#### シナリオ：アップロード中の切断
1. ファイル選択してアップロード開始
2. 数チャンク送信後にネットワーク切断
3. 以下のログを確認：

#### 期待されるログ
```
[DEBUG] ネットワーク切断 - 自動再開に任せます
Error: Network disconnected - waiting for auto-resume
[ConnectionManager] 再接続試行 #1
[ConnectionManager] 自動再開を開始します
```

#### 修正前の問題（出なくなること）
```
[DEBUG] 再接続を待機中...
[ConnectionManager] processAndUploadを呼び出します... ← 2回目の呼び出し
Payload 4 size: 22528 bytes ← 重複
Payload 4 size: 22528 bytes ← 重複
```

### 3. 2重実行の防止確認
- [ ] 同じペイロード番号が2回表示されないこと
- [ ] 同じチャンクに対して異なるTxIDが発行されないこと
- [ ] UIに重複した進捗が表示されないこと

### 4. 自動再開の正常動作
- [ ] 切断後の自動再開が1回のみ実行されること
- [ ] 中断した箇所から正しく再開すること
- [ ] 完了済みチャンクがスキップされること

## テストシナリオ

### シナリオ1：早期切断
1. ファイル選択（100チャンク程度）
2. 3-5チャンク送信後に切断
3. 再接続を待つ
4. 重複なく継続されることを確認

### シナリオ2：BlockID待機中の切断
1. アップロード開始
2. トランザクション送信直後（BlockID待機中）に切断
3. 再接続後の動作を確認
4. 同じペイロードが再送信されないこと

### シナリオ3：複数回切断
1. アップロード中に3回以上切断
2. 各回で重複実行が発生しないこと
3. 最終的に正しく完了すること

## デバッグ方法

### ログで確認すべき内容
```javascript
// processAndUpload呼び出し回数
grep "processAndUpload called" ログファイル | wc -l

// ペイロード重複チェック
grep "Payload [0-9]* size" ログファイル | sort | uniq -d
```

## 成功基準
- [ ] processAndUploadが同時に2つ実行されない
- [ ] トランザクション重複送信がない
- [ ] UI表示に重複がない
- [ ] コスト効率が改善される

## 注意事項
- v5.7.10により、ネットワークエラー時の処理が中断されるようになった
- これは意図的な動作で、自動再開機能に完全に依存する設計
- 手動での再接続試行は行われない

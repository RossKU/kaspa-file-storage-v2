# v5.7.5 テストチェックリスト

## テスト概要
v5.7.5では、ネットワークエラー時のRPCクライアント管理を改善しました。
「Attempt to use a disposed resource」エラーが解消されることを確認します。

## テスト手順

### 1. 基本動作確認
1. https://rossku.github.io/kaspa-file-storage-v2/kaspa-storage-webui-v5.7.5.html にアクセス
2. デバッグモードを有効にして、詳細ログを確認

### 2. ネットワーク切断テスト（最重要）

#### 手順
1. ファイルアップロードを開始
2. アップロード中にネットワークを切断（Wi-Fiオフ、機内モード等）
3. デバッグログを確認

#### 期待されるログ
```
[ConnectionManager] ネットワークエラーを検出
[ConnectionManager] RPC接続を切断しました
[ConnectionManager] RPCクライアントをクリアしました  ← 新規ログ
[ConnectionManager] 2000ms後に再接続を試行します
```

### 3. 再接続テスト

#### 手順
1. ネットワーク切断後、再度接続を有効化
2. 自動再接続の動作を確認

#### 期待されるログ
```
[ConnectionManager] 再接続試行 #1
[ConnectionManager] 新規RPCクライアントを作成します  ← 新規ログ
RPCクライアントを初期化中...
[ConnectionManager] RPC接続成功: kaspad/0.12.19
```

### 4. WebSocket切断テスト

#### 期待されるログ（WebSocket切断時）
```
[WebSocket] 切断イベントを検出
[WebSocket] RPCクライアントをクリアしました  ← 新規ログ
[ConnectionManager] 2000ms後に再接続を試行します
```

### 5. 異常系テスト

#### もし以下のログが出た場合
```
[ConnectionManager] 警告: RPCクライアントが残存していました
[ConnectionManager] 既存のRPCクライアントを破棄して新規作成します
```
これは予期しない状態ですが、自己修復するように実装されています。

### 6. 確認すべきエラーが出ないこと

#### 以下のエラーが出ないことを確認
- ❌ "Attempt to use a disposed resource"
- ❌ "Cannot read property 'getServerInfo' of null"
- ❌ "WebSocket is already in CLOSING or CLOSED state"

### 7. 複数回の切断・再接続テスト

1. ネットワーク切断 → 再接続を3回繰り返す
2. 毎回新しいRPCクライアントが作成されることを確認
3. メモリ使用量が増加し続けないことを確認（開発者ツールのMemoryタブ）

## トラブルシューティング

### 問題: 再接続が遅い
- 指数バックオフにより、失敗回数に応じて遅延が増加します
- 2秒 → 4秒 → 8秒 → 16秒 → 32秒 → 64秒 → 128秒（最大）

### 問題: ログが見えない
- デバッグモードが有効になっているか確認
- ブラウザコンソールでフィルタが適用されていないか確認

## 成功の判断基準

1. ✅ ネットワークエラー時にRPCクライアントが破棄される
2. ✅ 再接続時に新規クライアントが作成される
3. ✅ 「Attempt to use a disposed resource」エラーが出ない
4. ✅ 複数回の切断・再接続が安定して動作する

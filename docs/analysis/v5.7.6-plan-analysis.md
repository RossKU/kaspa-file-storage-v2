# v5.7.6 修正計画分析

## 現状の問題点

### 1. handleError関数の条件問題

#### 現在のコード構造
```javascript
async handleError(error, source) {
    // エラーチェック
    if (!isNetworkError(error)) {
        return false;
    }
    
    // この条件が問題
    if (this.isConnected) {
        this.isConnected = false;
        
        // v5.7.5: RPCクライアント破棄処理
        if (NetworkState.rpcClient) {
            // この処理に到達しないケースがある
        }
    }
}
```

#### 問題のシナリオ
1. WebSocket切断イベントが発生
2. イベントハンドラーで`ConnectionManager.isConnected = false`に設定
3. その後、handleErrorが呼ばれる
4. `if (this.isConnected)`がfalseのため、RPCクライアント破棄がスキップ

### 2. ループ問題の分析

#### タイムライン
```
21:45:03 WebSocket切断 → RPCクライアントをnull
21:45:04 再接続試行（1秒後）
21:45:05 RPCクライアント残存を検出
21:45:08 ネットワークエラー → handleError（処理スキップ）
21:45:14 再接続試行（指数バックオフ）
21:45:30 WebSocket切断（成功したが再び切断）
21:45:34 WebSocket切断（4秒後）
21:45:38 WebSocket切断（4秒後）
21:45:42 WebSocket切断（4秒後）
21:45:46 WebSocket切断（4秒後）
```

#### ループの原因
1. **早すぎる再接続**
   - baseReconnectDelay = 2000ms（2秒）
   - サーバー側の準備ができていない可能性

2. **処理の競合**
   - WebSocket切断イベント処理
   - ConnectionManagerのエラー処理
   - 再接続処理
   これらが非同期で競合

3. **状態管理の不整合**
   - 複数の場所でisConnectedを変更
   - RPCクライアントの状態と同期していない

## v5.7.6での修正方針

### 案1: handleErrorの条件を修正（最小限）
```javascript
async handleError(error, source) {
    if (!isNetworkError(error)) {
        return false;
    }
    
    // v5.7.6: Always cleanup RPC client first
    if (NetworkState.rpcClient) {
        try {
            await NetworkState.rpcClient.disconnect();
            log('[ConnectionManager] RPC接続を切断しました', 'info');
        } catch (disconnectError) {
            log(`[ConnectionManager] RPC切断エラー: ${disconnectError.message}`, 'debug');
        }
        NetworkState.rpcClient = null;
        log('[ConnectionManager] RPCクライアントをクリアしました', 'debug');
    }
    
    // Then update connection state
    if (this.isConnected) {
        this.isConnected = false;
        this.lastError = error;
        updateNetworkStatus('offline', 'ネットワークエラー');
        // ... 残りの処理
    }
}
```

### 案2: 重複処理の防止（より安全）
```javascript
async handleError(error, source) {
    if (!isNetworkError(error)) {
        return false;
    }
    
    // v5.7.6: Prevent duplicate processing
    if (!this.isConnected && !NetworkState.rpcClient) {
        log('[ConnectionManager] 既に切断処理済みです', 'debug');
        return true;
    }
    
    // Always cleanup
    if (NetworkState.rpcClient) {
        // ... クリーンアップ処理
    }
    
    // Update state
    if (this.isConnected) {
        // ... 状態更新
    }
}
```

## 推奨事項

### 短期的修正（v5.7.6）
- 案1を採用：最小限の変更でRPCクライアントを確実に破棄

### 中期的改善（将来）
1. **再接続遅延の調整**
   - baseReconnectDelay: 2000 → 5000ms
   - または動的調整

2. **状態管理の統一**
   - isConnectedとRPCクライアントの状態を同期
   - 単一の状態管理ポイント

3. **イベント処理の順序制御**
   - Promise chainやasync/awaitで順序を保証
   - 競合状態の排除

## リスク評価

- **低リスク**: RPCクライアントの破棄は冪等性がある
- **影響範囲**: エラー処理のみ
- **副作用**: 最小限

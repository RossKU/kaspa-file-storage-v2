# v5.7.7 技術的補足資料

## 実装コードの詳細タイミング分析

### 1. WebSocket切断イベントの伝播経路

```
[時刻 0ms] kaspa-core内部でWebSocket切断検出
    ↓
[時刻 1-5ms] RpcClient.emit('disconnect')
    ↓
[時刻 5-10ms] addEventListener('disconnect')ハンドラー実行（行11419）
    ├─ NetworkState.ws.connected = false（行11421）
    ├─ ConnectionManager.isConnected = false（行11425）
    ├─ NetworkState.rpcClient = null（行11431）← 即座にnull化
    └─ ConnectionManager.scheduleReconnect()（行11435）
         └─ setTimeout(() => attemptReconnect(), 2000)
```

### 2. エラー伝播の遅延問題

```
[時刻 0ms] processAndUploadでWebSocket切断エラー発生
    ↓
[時刻 100-500ms] catchブロックでエラー処理
    ↓
[時刻 500-1000ms] ConnectionManager.handleError呼び出し判定
    ↓
[時刻 4000-5000ms] handleError実際の実行（なぜこんなに遅い？）
    └─ この時点で既に再接続処理が進行中
```

### 3. 再接続処理の詳細

```javascript
// attemptReconnect（行3795）の実行タイミング
[時刻 2000ms] attemptReconnect開始
    ├─ [2001ms] NetworkState.rpcClient === null確認
    ├─ [2002ms] initializeRpcClient()呼び出し（行3808）
    │    ├─ [2003ms] createRpcClient()成功
    │    ├─ [2100ms] connect()成功
    │    ├─ [2101ms] updateNodeConnectionStatus()（行6380）
    │    │    └─ ❌ ReferenceError: updateNodeConnectionStatus is not defined
    │    └─ [2102ms] catchブロックでNetworkState.rpcClient = null（行6390）
    └─ [2103ms] getServerInfo()呼び出し（行3821）
         └─ ❌ TypeError: Cannot read properties of null
```

### 4. 複数のタイマーと非同期処理

現在のシステムには以下のタイマーが存在：

1. **再接続タイマー**（ConnectionManager）
   - 初回：2000ms
   - 指数バックオフ：2s → 4s → 8s → 16s → 32s

2. **監視タイマー**（WebSocket監視）
   - 5分タイマー（v5.7.2で修正済み）

3. **アップロードタイマー**
   - チャンク間隔：100ms
   - BlockID待機：最大30秒

### 6. 競合状態の具体例

```
ケース1：正常な再接続中にhandleErrorが実行
[0ms] WebSocket切断
[2000ms] attemptReconnect開始
[2100ms] RPC接続成功
[4000ms] handleError実行 → 接続中のRPCを破壊

ケース2：initializeRpcClient失敗中に別の切断
[0ms] 最初のWebSocket切断
[2000ms] attemptReconnect開始
[2101ms] updateNodeConnectionStatus失敗
[2102ms] NetworkState.rpcClient = null
[2500ms] 新たなWebSocket切断イベント
[4500ms] 2回目のattemptReconnect → 競合

ケース3：複数のエラーソースからの同時処理
- processAndUploadのエラー
- WebSocket切断イベント
- 監視タイムアウト
これらが同時に発生した場合の処理順序が不定
```

### 8. v5.7.7で優先すべき修正の技術的根拠

#### 最優先：updateNodeConnectionStatus削除
- **影響範囲**：initializeRpcClient内の1行のみ
- **副作用**：なし（UI更新のみ）
- **効果**：再接続が成功するようになる

#### 次優先：nullチェック追加
- **影響範囲**：attemptReconnect内の3行追加
- **副作用**：なし（防御的プログラミング）
- **効果**：null参照エラーを防止

#### 3番目：再接続ロック
- **影響範囲**：ConnectionManagerに状態追加
- **副作用**：タイミング依存の可能性
- **効果**：競合状態を防止

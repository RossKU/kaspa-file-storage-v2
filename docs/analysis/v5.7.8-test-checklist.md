# v5.7.8 テストチェックリスト

## 概要
v5.7.8では、"output already spent"エラーの特別処理を追加し、誤ったエラー表示を防ぐ改善を行いました。

## 重要な確認ポイント

### 1. 正常なアップロード処理
- [ ] ファイルアップロードが通常通り動作すること
- [ ] "already accepted"エラーが引き続き正しく処理されること
- [ ] エラーなしで完了すること

### 2. "output already spent"エラーの処理

#### シナリオ：切断→再接続時
1. アップロード開始
2. ネットワークを切断（トランザクション送信直後）
3. 再接続を待つ
4. 以下のログを確認：

#### 期待されるログ（新機能）
```
ペイロード X は既に自分のトランザクションで処理済み: [TxID]...
```

#### 修正前に出ていたエラー（出なくなること）
```
ペイロード X エラー: output already spent by transaction [自分のTxID]
```

### 3. 他者のトランザクションによるspentエラー
- [ ] 他者が同じUTXOを使った場合は、通常のエラーとして処理されること
- [ ] リトライが正常に動作すること

### 4. デバッグ情報の確認

#### コンソールで確認
```javascript
// monitoredTransactionsの状態確認
console.log('Monitored TXs:', NetworkState.ws.monitoredTransactions);

// 特定のトランザクションの確認
NetworkState.ws.monitoredTransactions.forEach((data, txId) => {
    console.log(`TxID: ${txId}, BlockID: ${data.blockId}`);
});
```

## テストシナリオ

### シナリオ1：即座の切断
1. ファイル選択してアップロード開始
2. 最初のチャンク送信直後にネットワーク切断
3. 5秒待って再接続
4. エラーではなく成功として処理されることを確認

### シナリオ2：複数回の切断
1. アップロード中に複数回切断・再接続
2. 各回で適切なエラー処理がされること
3. 最終的にアップロードが完了すること

### シナリオ3：長時間の切断
1. トランザクション送信後、30秒以上切断
2. 再接続後の処理を確認
3. 適切なエラーメッセージが表示されること

## ログの見方

### 成功パターン
```
[INFO] ペイロード 1 は既に自分のトランザクションで処理済み: 1234abcd...
[SUCCESS] チャンク 1/10 完了
```

### エラーパターン（他者のトランザクション）
```
[ERROR] ペイロード 1 エラー: output already spent by transaction [他者のTxID]
[INFO] 2秒待機後にリトライ...
```

## 注意事項
- v5.7.8の改善により、誤ったエラー表示が大幅に減少するはず
- ただし、ネットワークの状態により、まれに想定外の動作をする可能性がある
- その場合は詳細なログを確認して原因を特定すること

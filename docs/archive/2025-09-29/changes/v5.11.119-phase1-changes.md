# v5.11.119 Phase 1: アーカイブノードnullチェック修正（Ultrathink）

## 概要
v5.11.119で発生したnull参照エラーを修正。アーカイブノードが利用できない場合の適切なエラーハンドリングを実装。

## 修正内容

### switchToArchiveNode()呼び出しの修正（14544-14591行）

**変更前**：
```javascript
const switched = await switchToArchiveNode();  // 未定義関数
if (switched) {
    const blockResponse = await NetworkState.rpcClient.getBlock({
```

**変更後**：
```javascript
// Try to use archive node via ArchiveNodeManager
let archiveClient = null;
if (NetworkState.archiveManager && NetworkState.archiveManager.connections.size > 0) {
    try {
        archiveClient = await NetworkState.archiveManager.getOptimalClient();
    } catch (e) {
        log(`[RPC] アーカイブノード取得エラー: ${e.message}`, 'error');
    }
}

if (archiveClient) {
    // Retry the operation with archive node
    log(`[RPC] アーカイブノードで再試行中...`, 'info');
    try {
        const blockResponse = await archiveClient.getBlock({
            // ... 処理
        });
    } catch (archiveError) {
        log(`[RPC] アーカイブノードでもエラー: ${archiveError.message}`, 'error');
        throw rpcError; // 元のエラーを再throw
    }
} else {
    log(`[RPC] 利用可能なアーカイブノードがありません`, 'warning');
    throw rpcError;
}
```

## 改善点

1. **nullチェックの追加**
   - `archiveClient`がnullの場合の処理を明確化
   - 「disconnected from all chains」エラーを防止

2. **エラーハンドリング強化**
   - try-catchでアーカイブノード取得時のエラーをキャッチ
   - アーカイブノードでの処理もtry-catchで保護

3. **ログ出力の改善**
   - アーカイブノードが利用できない場合の警告
   - エラー発生時の詳細ログ

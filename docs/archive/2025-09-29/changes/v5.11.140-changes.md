# v5.11.140: 2ノードリッスン専用実装

## 概要
シンプルな2ノード監視実装。メインRPCは従来通り、補助RPCは監視専用で同じResolverを使用します。

## 主な変更内容

### 1. NetworkState拡張
```javascript
auxRpcClient: null,         // 単一の補助RPC
rpcScores: { main: 0, aux: 0 }  // 検出スコア記録
```

### 2. 監視開始時の処理
- メインRPC: subscribeBlockAdded → すぐaddEventListener
- 補助RPC: subscribeBlockAdded → すぐaddEventListener（同じブロック内）
- トランザクションID取得方法を統一（3つの方法を試す）

### 3. スコア追跡
- 最初にBlockIDを検出したRPCがスコア獲得
- 「🏆 [補助RPC] 最速でBlockID検出」表示
- スコア表示でどちらが速いか確認可能

### 4. 適切なクリーンアップ
- stopMonitoring時に補助RPCも停止
- メモリリーク防止

## 期待される効果
- BlockID検出の高速化（2つのノードで競争）
- シンプルな実装（送信はメインRPCのみ）
- 同じResolverでも異なるノードに接続される可能性

## 技術的詳細

### 実装の特徴
- subscribeの直後にaddEventListenerを設定（重要）
- トランザクションID取得を3つの方法で試す（互換性向上）
- 補助RPCは監視のみ（送信しない）

### エラーハンドリング
- 補助RPC接続失敗時もメインRPCで継続
- エラーは警告ログのみ（処理は停止しない）

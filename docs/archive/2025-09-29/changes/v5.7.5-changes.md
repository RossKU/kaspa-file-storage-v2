# v5.7.5 変更内容

## 修正内容
ネットワークエラー時にRPCクライアントが適切に破棄されず、「Attempt to use a disposed resource」エラーが発生する問題を修正しました。

### 変更箇所

#### 1. ConnectionManager.handleError関数（3731-3741行目）
- エラー検出時にRPCクライアントを破棄
- disconnect()を呼び出してからnullに設定

#### 2. ConnectionManager.attemptReconnect関数（3788-3803行目）
- 常に新しいRPCクライアントを作成
- 残存クライアントがある場合は警告ログを出力

#### 3. WebSocket disconnectイベントハンドラー（11405-11411行目）
- WebSocket切断時にRPCクライアントをnullに設定
- ConnectionManager.scheduleReconnect()を呼び出し

#### 4. initializeRpcClient関数（6362行目）
- 変数参照ミスを修正（rpcClient → NetworkState.rpcClient）

## 修正前の問題
```javascript
// エラー発生後も古いRPCクライアントが残る
NetworkState.rpcClient // <- 切断されたWebSocketを持つゾンビ状態

// 再接続時に壊れたクライアントで操作
await NetworkState.rpcClient.getServerInfo() // <- エラー発生
```

## 修正後の動作
```javascript
// エラー発生時
NetworkState.rpcClient = null // クリーンアップ

// 再接続時
await initializeRpcClient() // 新しいクライアントを作成
```

## 解決される問題
1. **「Attempt to use a disposed resource」エラー**: 切断されたクライアントへの操作を防止
2. **メモリリーク**: ゾンビRPCクライアントの蓄積を防止
3. **再接続の信頼性**: 常に新しい接続で再開

## デバッグログ
以下のログで動作を確認できます：
```
[ConnectionManager] RPCクライアントをクリアしました
[ConnectionManager] 新規RPCクライアントを作成します
[WebSocket] RPCクライアントをクリアしました
[ConnectionManager] 警告: RPCクライアントが残存していました（異常時のみ）
```

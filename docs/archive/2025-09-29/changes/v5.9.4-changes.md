# v5.9.4 変更内容

## 概要
スーパーメタデータの中間メタデータへのchunkBoundaries分配ロジックを修正しました。

## 修正された問題

### 1. chunkBoundaries分配の不具合
**問題**：
- 全てのchunkBoundariesが最初の中間メタデータに格納されていた
- 2番目以降の中間メタデータにはchunkBoundariesが含まれていなかった

**原因**：
```javascript
// 誤ったコード（v5.9.3以前）
chunkBoundaries: fileMetadata.metadata.chunkBoundaries.slice(
    groupIndex * chunksPerMeta,  // 例: 0 * 160 = 0
    (groupIndex + 1) * chunksPerMeta  // 例: 1 * 160 = 160
)
```
- chunkBoundariesのインデックスとチャンク番号を混同していた
- chunkBoundariesは5個程度しかないのに、160個分をスライスしようとしていた

### 2. 修正内容（更新版）

**初回の修正（誤り）**：
```javascript
// boundary.indexを使用（これは圧縮チャンクのインデックス0-4）
const chunkIndex = boundary.index;
return chunkIndex >= startChunk && chunkIndex <= endChunk;
```

**正しい実装（修正済み）**：
```javascript
// v5.9.4の最終修正
const boundariesForGroup = fileMetadata.metadata.chunkBoundaries.filter(boundary => {
    // boundary.payloadIndexは、そのバウンダリーが開始するペイロードのインデックス
    const payloadStartIndex = boundary.payloadIndex;
    return payloadStartIndex >= startChunk && payloadStartIndex <= endChunk;
});
```

### 3. データ構造の理解
```javascript
// chunkBoundaryの構造
{
    index: 0,           // 圧縮チャンクのインデックス（0-4）
    payloadIndex: 0,    // 開始ペイロードのインデックス（0, 46, 93, 139, 186）
    offset: 0,          // バイトオフセット
    size: 1048592       // 圧縮チャンクのサイズ（約1MB）
}
```

## 影響範囲
- payloadSplit方式でアップロードされた大きなファイル（>3.5MB）
- スーパーメタデータを使用するファイル（160チャンク以上）

## 互換性
- 既存のファイルは影響を受けません
- v5.9.3以前でアップロードされたファイルも正常にダウンロード可能

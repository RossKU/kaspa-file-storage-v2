# v6.2.30 Changes - Fix .kaspa File CID to Use 8-character Short Version

## Date: 2025-08-20

## Problem
The .kaspa file generation was using the full 43-character CID instead of the expected 8-character short CID, resulting in unnecessarily long filenames.

## Root Cause Analysis
1. **CID Generation** (line 9381-9409):
   - `full`: 43-character full Base64 hash
   - `display`: First 8 characters (short CID)

2. **Storage During Upload** (line 12597-12604):
   - `window.currentFileCIDFull`: 43 characters
   - `window.currentFileCID`: 8 characters

3. **KENV Entry Assignment Issue** (line 13781):
   - Before: `kenvEntry.cid = window.currentFileCIDFull || window.currentFileCID || '';`
   - Full CID was prioritized over short CID

4. **.kaspa Filename Generation** (line 5830-5831):
   - Used `kenvEntry.cid` resulting in 43-character CID in filename

## Solution
Changed the CID assignment priority to use short CID first:

### Modified KENV CID Assignment (line 13781)
```javascript
// Before:
kenvEntry.cid = window.currentFileCIDFull || window.currentFileCID || '';

// After:
kenvEntry.cid = window.currentFileCID || window.currentFileCIDFull?.slice(0, 8) || '';
```

## Impact
- .kaspa filenames now use 8-character short CID as intended
- Example: `document.aBcDeFgH.kaspa` instead of `document.aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789ABCDE.kaspa`
- No data loss: Full CID is still stored in metadata
- Better filename readability and usability

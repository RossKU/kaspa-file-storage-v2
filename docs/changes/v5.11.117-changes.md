# v5.11.117: トランザクション保持ロジック改善（Ultrathink）

## 変更内容

### 問題
- 受信時に即座に削除していたため、WebSocket遅延時に検出できない
- 送信から90秒で削除していたため、ネットワーク遅延に対応できない

### 解決策
「受信してから90秒で削除」に変更

### 3. クリーンアップロジック改善（15759-15775行目）
```javascript
if (txData.receivedAt) {
    // Received: delete 90 seconds after receipt
    if (now - txData.receivedAt > 90000) {
        NetworkState.ws.monitoredTransactions.delete(txid);
    }
} else {
    // Not received: delete 300 seconds after transmission
    if (now - txData.timestamp > 300000) {
        NetworkState.ws.monitoredTransactions.delete(txid);
    }
}
```

## メリット

### 1. タイムアウト独立性
- waitForConfirmationのタイムアウトが何分でも対応可能
- クリーンアップとタイムアウトが分離

### 2. WebSocket遅延対応
- 200秒遅延してもトランザクションを検出可能
- ネットワーク不安定時でも高い信頼性

### 3. 重複検出
- 同じトランザクションが複数ブロックで検出されても対応
- 90秒間は情報を保持

### 4. メモリ効率
- 受信済みは90秒で削除
- 未受信は300秒で削除
- メモリリークを防止

# v5.7.7 変更内容

## 修正内容
v5.7.6で発生した再接続不能の問題を修正し、安定した再接続機能を復旧しました。

### 主な変更点

#### 1. updateNodeConnectionStatus関数呼び出しの削除（行6380-6381）
```javascript
// v5.7.7: Commented out undefined function call
// updateNodeConnectionStatus(config.nodeType, config.currentEndpoint);
```
- **問題**: この関数は一度も定義されていないため、ReferenceErrorが発生
- **影響**: initializeRpcClient関数が必ず失敗し、再接続不能に
- **解決**: 呼び出しをコメントアウト

#### 2. attemptReconnectにnullチェック追加（行3817-3820）
```javascript
// v5.7.7: Null check before getServerInfo
if (!NetworkState.rpcClient) {
    throw new Error('RPC client initialization failed');
}
```
- **問題**: initializeRpcClient失敗後、nullのRPCクライアントでgetServerInfoを呼ぶ
- **影響**: "Cannot read properties of null" エラー
- **解決**: 明示的なnullチェックと適切なエラーハンドリング

#### 3. 再接続ロックメカニズムの実装
```javascript
// ConnectionManagerに追加（行3719）
isReconnecting: false,  // v5.7.7: Prevent concurrent reconnection attempts

// attemptReconnect関数の開始（行3797-3801）
if (this.isReconnecting) {
    log('[ConnectionManager] 既に再接続中です', 'debug');
    return;
}
this.isReconnecting = true;

// 成功時と失敗時にリセット（行3837, 3842）
this.isReconnecting = false;
```
- **問題**: 複数の再接続試行が同時に実行される可能性
- **影響**: 競合状態とリソースの無駄
- **解決**: 排他制御により同時実行を防止

## 技術的背景

### なぜv5.7.6で問題が発生したか
1. updateNodeConnectionStatus関数は過去のバージョンから存在していたが、通常の使用では呼ばれない
2. v5.7.6のhandleError修正により、再接続処理が頻繁に実行されるようになった
3. その結果、今まで潜在していた問題が顕在化

### 修正の影響
- **再接続機能**: 完全に復旧
- **メモリリーク**: 防止
- **パフォーマンス**: 改善（重複処理の排除）

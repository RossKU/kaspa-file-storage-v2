# v6.2.56: Fix XSS vulnerability in directory tree rendering

## Security Fix
- **Fixed critical XSS vulnerability** in directory tree rendering (lines 6534, 6548, 6552, 6079, 6092)
- Added `escapeHtml()` function to sanitize user-controlled data
- Applied HTML escaping to:
  - `node.name` - Directory and file names
  - `node.fullPath` - Full path in onclick handlers  
  - `node.type` - Node type in onclick handlers

## Technical Implementation
- Created centralized `escapeHtml()` function (line 6151-6159)
- Escapes dangerous characters: `& < > " '`
- Applied to all instances where user input is rendered in HTML

## Analysis of Other innerHTML Uses
Analyzed and determined the following are **NOT vulnerabilities**:
- **Restart status** (line 3617) - Static content only, no user input
- **File size display** (line 7929) - Numeric values only (file.size)
- **Archive details** (line 11392) - Numeric statistics only
- **Log entry** (line 9480) - Message is properly escaped, time/type are safe

## Testing
Test with malicious directory/file names:
```bash
mkdir "/storage/emulated/0/Download/<script>alert('XSS')</script>"
touch "/storage/emulated/0/Download/<img src=x onerror=alert('Hacked')>.txt"
```
These will now display safely as text without executing scripts.

## Summary
- **Fixed:** 1 major XSS vulnerability (directory tree with 5 injection points)
- **Verified Safe:** 4 other innerHTML uses (no user input)
- **Total XSS fixes so far:** 7 vulnerabilities across v6.2.54-v6.2.56

The application is now significantly more secure against XSS attacks.

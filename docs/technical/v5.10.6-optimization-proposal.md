# v5.10.6 Entriesフィールド最適化提案

## 📊 提案内容

### 1. pathフィールドの最適化

#### 現在の仕槕（v3.3.0）
```json
{
  "name": "document.pdf",
  "path": "folder1/folder2/document.pdf"  // フルパス
}
```

#### 提案
```json
{
  "name": "document.pdf",
  "path": "folder1/folder2"  // ディレクトリパスのみ
  // ルートフォルダ直下の場合: "path": ""
}
```

#### メリット
- ✅ **データサイズ削減**: 重複情報の除去
- ✅ **シンプル**: nameとpathを結合すればフルパスを復元可能
- ✅ **一貫性**: ディレクトリ構造が明確

#### デメリット
- ⚠️ **仕槕変更**: v3.3.0仕槕からの逸脱
- ⚠️ **後方互換性**: 既存データの処理が必要

### 2. フィールド順序の最適化

#### 現在の順序（v3.3.0仕槕）
```javascript
{
  type: 'file',
  name: 'document.pdf',
  path: 'folder1/folder2/document.pdf',
  size: 1234567,
  metaTxId: "...",
  blockId: "...",
  password: "...",
  cid: "..."
}
```

#### 提案の順序
```javascript
{
  path: 'folder1/folder2',  // ディレクトリ情報を最初に
  type: 'file',
  name: 'document.pdf',
  size: 1234567,
  cid: "bafybeif...",      // ファイル識別情報
  metaTxId: "...",         // ブロックチェーン情報
  blockId: "...",
  password: "..."          // オプション情報
}
```

#### メリット
- ✅ **論理的グルーピング**: 位置→基本情報→識別子→オプション
- ✅ **可読性**: 人間にとって理解しやすい
- ✅ **パフォーマンス**: ディレクトリ別処理が容易

### 3. CIDフィールドの完全性

#### 現在の実装
```json
"cid": "xWqyXRLP"  // 短縮CID
```

#### 提案
```json
"cid": "bafybeifxwqyxrlp..."  // 完全なCID
```

#### メリット
- ✅ **完全性**: ファイルの一意識別が可能
- ✅ **検証性**: ファイル内容の整合性確認が可能
- ✅ **標準準拠**: IPFS CIDフォーマット

## 🔧 実装方法

### オプション1: 仕槕拡張（v3.4.0）

新しいバージョンを定義し、pathフィールドの意味を変更：

```javascript
{
  "type": "kaspa-directory",
  "version": "3.4",  // 新バージョン
  "formatNotes": {
    "pathBehavior": "directory-only"  // pathはディレクトリのみ
  }
}
```

### オプション2: 後方互換モード

既存の仕槕を維持し、読み込み時に最適化：

```javascript
// 読み込み時
if (entry.path.endsWith(entry.name)) {
  // 古い形式（フルパス）を検出
  entry.dirPath = entry.path.replace(new RegExp(`/${entry.name}$`), '');
} else {
  // 新しい形式（ディレクトリのみ）
  entry.dirPath = entry.path;
}
```

### オプション3: ハイブリッド方式

両方のフィールドを保持：

```javascript
{
  "name": "document.pdf",
  "path": "folder1/folder2/document.pdf",  // 後方互換性のため
  "dirPath": "folder1/folder2",            // 新フィールド
  "cid": "bafybeif..."
}
```

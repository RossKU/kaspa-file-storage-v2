# v5.7.5 RPC接続クリーンアップ実装計画

## 問題の概要
現在、ネットワークエラー発生時にRPCクライアントが適切に破棄されず、切断されたWebSocketを持つ「ゾンビ」状態のクライアントが残存している。これが「Attempt to use a disposed resource」エラーの原因となっている。

## 根本原因
1. ConnectionManagerがエラーを検出してもRPCクライアントを破棄しない
2. WebSocket切断後も古いRPCクライアントオブジェクトが残る
3. 再接続時に壊れたクライアントで操作を試みる

## 修正方針
エラー発生時に既存のRPCクライアントを確実に破棄し、再接続時は常に新しいRPCクライアントを作成する。

## 段階的実装計画

### Phase 1: 最小限の修正（v5.7.5）
**目的**: エラー時のRPCクライアント破棄を実装

#### 1.1 handleError関数の修正
```javascript
async handleError(error, source) {
    // ... 既存のコード ...
    
    if (this.isConnected) {
        this.isConnected = false;
        this.lastError = error;
        
        // v5.7.5: Cleanup RPC client on network error
        if (NetworkState.rpcClient) {
            try {
                await NetworkState.rpcClient.disconnect();
                log('[ConnectionManager] RPC接続を切断しました', 'info');
            } catch (disconnectError) {
                log(`[ConnectionManager] RPC切断エラー: ${disconnectError.message}`, 'debug');
            }
            NetworkState.rpcClient = null;
            log('[ConnectionManager] RPCクライアントをクリアしました', 'debug');
        }
        
        updateNetworkStatus('offline', 'ネットワークエラー');
        // ... 既存のコード ...
    }
}
```

#### 1.2 attemptReconnect関数の修正
```javascript
async attemptReconnect() {
    this.reconnectAttempts++;
    log(`[ConnectionManager] 再接続試行 #${this.reconnectAttempts}`, 'info');
    
    try {
        // v5.7.5: Always create new RPC client on reconnect
        if (!NetworkState.rpcClient) {
            await initializeRpcClient();
        } else {
            // This should not happen if handleError works correctly
            log('[ConnectionManager] 警告: RPCクライアントが残存していました', 'warning');
            await initializeRpcClient();
        }
        
        // Test connection
        const info = await NetworkState.rpcClient.getServerInfo();
        log(`[ConnectionManager] RPC接続成功: ${info.serverVersion}`, 'success');
        
        await this.handleReconnected();
    } catch (error) {
        log(`[ConnectionManager] 再接続失敗: ${error.message}`, 'error');
        this.scheduleReconnect();
    }
}
```

#### 1.3 WebSocket切断イベントハンドラーの修正
```javascript
NetworkState.rpcClient.addEventListener('disconnect', (event) => {
    log('[WebSocket] 切断イベントを検出', 'warning');
    NetworkState.ws.connected = false;
    
    // v5.7.5: Ensure RPC client is cleaned up on WebSocket disconnect
    if (ConnectionManager.isConnected) {
        ConnectionManager.isConnected = false;
        ConnectionManager.lastError = new Error('WebSocket disconnected via event');
        updateNetworkStatus('offline', 'WebSocket切断');
        
        // Clean up RPC client
        if (NetworkState.rpcClient) {
            NetworkState.rpcClient = null;
            log('[WebSocket] RPCクライアントをクリアしました', 'debug');
        }
        
        ConnectionManager.scheduleReconnect();
    }
});
```

## リスク評価

### リスク
1. **disconnect()の副作用**: 一部の状態が予期せずリセットされる可能性
2. **タイミング問題**: 複数の箇所から同時にクリーンアップが実行される可能性
3. **進行中の処理**: アップロード中にRPCクライアントが破棄される可能性

### 対策
1. try-catchで安全にdisconnect()を実行
2. NetworkState.rpcClient = nullでオブジェクト参照を確実に切断
3. 詳細なデバッグログで動作を追跡

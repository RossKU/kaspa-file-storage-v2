# v6.2.5 Changes - Fix UTXO Consolidation Transaction Creation

## 🔧 Critical Bug Fix

### Problem
- **"Insufficient funds" error** despite having 1975 KAS balance
- Caused by incorrect transaction parameter usage
- `fee` parameter doesn't exist in Kaspa SDK

### Solution
- **Removed invalid `fee` parameter**
- **Increased estimated fee to 0.001 KAS** (100000 sompi) for safety margin
- **Send balance minus estimated fee** to self
- SDK automatically calculates actual fee from the transaction

### Technical Changes

#### Before (Incorrect)
```javascript
const fee = 10000n; // Invalid parameter
const consolidatedAmount = totalBalance - fee;

result = await NetworkState.kaspa.createTransactions({
    entries: formattedUtxos,
    outputs: [{
        address: UserState.address.toString(),
        amount: consolidatedAmount
    }],
    changeAddress: UserState.address.toString(),
    priorityFee: 0n,
    fee: 10000n,  // ❌ This parameter doesn't exist!
    ...
});
```

#### After (Correct)
```javascript
const estimatedFee = 100000n; // 0.001 KAS (generous estimate)
const consolidatedAmount = totalBalance - estimatedFee;

// Validate amount
if (consolidatedAmount <= 0n) {
    throw new Error(`Balance too low for consolidation...`);
}

result = await NetworkState.kaspa.createTransactions({
    entries: formattedUtxos,
    outputs: [{
        address: UserState.address.toString(),
        amount: consolidatedAmount  // Send all minus estimated fee
    }],
    changeAddress: UserState.address.toString(),
    priorityFee: 0n,  // SDK calculates actual fee
    // No 'fee' parameter - it doesn't exist
    ...
});
```

### Key Points
- **Estimated fee**: 0.001 KAS (10x typical fee for safety)
- **Actual fee**: Calculated by SDK (usually ~0.0001 KAS)
- **Refund**: Excess fee automatically returned as change
- **Result**: All UTXOs consolidated into 1-2 outputs

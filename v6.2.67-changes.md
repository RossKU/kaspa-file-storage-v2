# v6.2.67 Changes - Meta Transaction REST API Fallback Fix

## 🐛 Bug Fix
Fixed critical bug in meta transaction REST API fallback that was preventing recovery after WebSocket disconnection.

### Problem
When WebSocket disconnected during meta transaction BlockID waiting, the REST API fallback would fail with:
```
Cannot read properties of undefined (reading 'enabled')
```

### Root Cause
Line 14894 incorrectly accessed `config.restApiControl.enabled` instead of `NetworkState.restApiControl.globalEnabled`.

### Solution
Changed the condition check from:
```javascript
if (waitTime >= config.restApiWaitTime && config.restApiControl.enabled) {
```

To:
```javascript
if (waitTime >= config.restApiWaitTime && NetworkState.restApiControl.globalEnabled) {
```

### Impact
- Meta transactions can now properly fall back to REST API when WebSocket disconnects
- Consistent with regular chunk and super meta handling
- Prevents upload failures during network instability

### Testing
Verified that:
- No other instances of `config.restApiControl` remain in the code
- Pattern matches regular chunk handling (line 12442) and super meta handling (line 15190)
- REST API fallback will now trigger after 10 seconds when enabled

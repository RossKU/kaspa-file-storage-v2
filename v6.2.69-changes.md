# v6.2.69 Changes - Fix Meta Transaction WebSocket Disconnect Handling

## 🐛 Critical Bug Fix
Fixed meta transaction retry logic to properly handle WebSocket disconnections.

### Problem
v6.2.68 would retry meta transaction submission even when WebSocket was disconnected, resulting in:
- Meaningless retry attempts during disconnection
- All 3 retries failing while waiting for reconnection
- Transaction failure even though reconnection would succeed later

### Root Cause Analysis
The previous implementation would:
1. Detect WebSocket disconnect error
2. Wait 2 seconds
3. Retry while still disconnected (guaranteed to fail)
4. Repeat until max retries exhausted

Meanwhile, regular chunks correctly:
1. Detect disconnection via ConnectionManager.isConnected
2. Immediately throw error to stop retrying
3. Let auto-resume handle it after reconnection

### Solution
Aligned meta transaction behavior with regular chunks:
```javascript
// Check connection status before retry
if (!ConnectionManager.isConnected) {
    log('[DEBUG] ネットワークDisconnect - 自動再開に任せます', 'debug');
    throw new Error('Network disconnected - waiting for auto-resume');
}
```

### Impact
- Meta transactions now properly abort on disconnect
- Auto-resume will handle them after reconnection
- No more wasted retry attempts during disconnection
- Consistent behavior with regular chunk uploads

### Testing
1. Start uploading a file with meta transaction
2. Disconnect network during meta tx creation
3. Observe immediate abort (not multiple retries)
4. Auto-resume should handle it after reconnection

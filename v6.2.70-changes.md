# v6.2.70 Changes - Fix REST API Spam in Meta Transaction BlockID Waiting

## 🐛 Critical Bug Fix
Fixed meta transaction REST API spam - now properly calls REST API once every 10 seconds instead of every 500ms.

### Problem
v6.2.69 had a critical bug where after 10 seconds elapsed, the meta transaction BlockID waiting logic would call REST API every 500ms continuously:
- Once `waitTime >= config.restApiWaitTime` became true (at 10 seconds)
- It remained true forever
- REST API was called on every loop iteration (500ms intervals)
- This created hundreds of unnecessary API calls

### Root Cause
Missing `lastApiCheck` timer tracking in meta transaction code. Regular chunks had proper interval tracking, but meta transactions didn't.

### Solution 
Added the same interval tracking pattern used by regular chunks:
```javascript
// Before (buggy):
if (waitTime >= config.restApiWaitTime) {  // Always true after 10 seconds
    // REST API call (executed every 500ms)
}

// After (fixed):
let lastApiCheck = 0;  // Track last API call time
if (waitTime - lastApiCheck >= 10000) {  // Only true every 10 seconds
    // REST API call
    lastApiCheck = waitTime;  // Reset timer
}
```

### Technical Details
**Modified section**: Lines 14889 and 14914-14933
- Added `lastApiCheck` variable initialization at line 14889
- Changed REST API condition from `waitTime >= config.restApiWaitTime` to `waitTime - lastApiCheck >= 10000`
- Added `lastApiCheck = waitTime` after API call to reset timer
- Now exactly matches regular chunk behavior at line 13589

### Impact
- REST API is now called maximum once every 10 seconds (as intended)
- No more API spam after WebSocket reconnection
- Consistent behavior between regular chunks and meta transactions
- Reduced server load and better performance

This was the final issue preventing proper WebSocket disconnection handling for meta transactions. Now meta transactions behave identically to regular chunks:
1. Use WebSocket monitoring when connected
2. Fall back to REST API (once per 10 seconds) when disconnected
3. No wasteful API spam
4. Proper reconnection handling

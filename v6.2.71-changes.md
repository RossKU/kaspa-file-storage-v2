# v6.2.71 Changes - Fix Meta Transaction Auto-Resume

## 🐛 Critical Bug Fix
Fixed meta transaction network errors not preserving ProgressManager, preventing auto-resume after reconnection.

### Problem
When network disconnection occurred during meta transaction creation:
1. Error was thrown correctly ✅
2. But `networkErrorOccurred` flag was NOT set ❌
3. Finally block would reset ProgressManager ❌
4. Auto-resume couldn't work after reconnection ❌

### Root Cause Analysis
The difference between regular chunks and meta transactions:

| Phase | Regular Chunks | Meta Tx (v6.2.70) |
|-------|---------------|-------------------|
| Network Error Detection | ✅ Sets `networkErrorOccurred` | ❌ Doesn't set flag |
| ProgressManager Retention | ✅ Preserved | ❌ Reset in finally |
| Auto-Resume | ✅ Works | ❌ Can't resume |

### Solution
Added `networkErrorOccurred` flag setting in meta transaction catch block:
```javascript
// v6.2.71: Set networkErrorOccurred flag for network errors
if (isNetworkError(error)) {
    FileState.networkErrorOccurred = true;
    log('[INFO] メタTx作成でネットワークエラーを検出 - ProgressManagerを保持します');
}
```

### Impact
- Meta transactions now behave identically to regular chunks on network errors
- ProgressManager is preserved during network disconnections
- Auto-resume works correctly after reconnection
- Complete consistency between chunk and meta tx error handling

### Testing
To verify the fix:
1. Upload a file (single chunk works)
2. During meta tx creation, disconnect network
3. Reconnect network
4. Auto-resume should now trigger and complete the meta tx

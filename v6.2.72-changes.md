# v6.2.72 Changes - Fix WebSocket Recovery for Meta Transactions

## 🐛 Critical Bug Fix
Fixed WebSocket recovery mechanism to properly handle transactions confirmed during disconnection.

### Problem
When WebSocket disconnected during meta transaction BlockID waiting:
1. Meta tx was sent successfully
2. WebSocket disconnected
3. **Transaction confirmed during disconnection** 
4. WebSocket reconnected
5. **Block was never received again** (WebSocket only sends NEW blocks)
6. Meta tx stuck waiting forever

### Root Cause
WebSocket event streams only notify about **new blocks**. If a transaction is confirmed while disconnected, that block event is lost forever. The monitoring list preserved the transaction, but there was no mechanism to check past confirmations after reconnection.

### Solution
Added RPC verification for pending transactions after WebSocket reconnection:
```javascript
// v6.2.72: After reconnection, check pending transactions via RPC
for (const [txId, data] of NetworkState.ws.monitoredTransactions.entries()) {
    if (!data.blockId) {
        const txInfo = await NetworkState.rpcClient.getTransaction(txId, true);
        if (txInfo && txInfo.blockHash) {
            data.blockId = txInfo.blockHash[0];
            // Transaction was confirmed during disconnection!
        }
    }
}
```

### Impact
- Transactions confirmed during disconnection are now properly detected
- WebSocket recovery actually works for meta transactions
- No more stuck meta tx after reconnection
- Complete resilience against network interruptions
